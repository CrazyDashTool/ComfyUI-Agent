## Supported formats

Native ComfyUI 3D nodes accept these formats from the input folders:

- Meshes: `gltf`, `glb`, `obj`, `fbx`, `stl`.
- Gaussian splats and point clouds: `spz`, `splat`, `ksplat`, `ply`.
- Other packs may add `usdz`, `3ds`, `dae` and `abc`; check the pack docs.

`glb` is the most portable output format because it packs geometry, materials and textures into one file.

The node for every 3D job is `Load3D`, shown in the canvas as "Load 3D & Animation". See the "Native nodes and what they are for" reference for the full node map.

## Where 3D files live

- Input files, including subfolders such as `3d/`, are listed by `list_assets(kind="3d")`.
- The `Load3D` widget is `model_file` and its values come from the input folder; a subfolder is part of the value, for example `3d/robot.glb`.
- A 3D file attached in this chat is uploaded to `input/3d/` and the agent receives its exact stored path.
- Output models are written by `SaveGLB` or `Save3DAdvanced` to the output folder, not automatically to input.

## Native 3D nodes

- `Load3D` ("Load 3D & Animation"): loads a model and also exposes rendered image, mask, normal, mesh path, camera info, recording and mesh info outputs. Widget: `model_file`.
- `Load3DAdvanced`: viewport and camera inputs for more control.
- `Preview3D` and `Preview3DAdvanced`: display a model in the viewer; `Preview3D` is deprecated in favor of the advanced node.
- `SaveGLB`: writes mesh data to a `.glb` file.
- `MeshToFile3D`: converts a mesh to a file path.
- `RotateMesh`, `MergeMeshes`, `GetMeshInfo`: geometry utilities.
- `Save3DAdvanced`, `SaveGaussianSplat`, `SavePointCloud`: output nodes for their data types.
- `PreviewGaussianSplat`, `PreviewPointCloud`: viewers for splat and point-cloud outputs.

Use `get_node_info` on these class names to see the installed input names; do not assume a widget name from memory.

## Common 3D workflows

### Turntable or preview render

`Load3D` -> `Preview3DAdvanced` (or `SaveGLB` for a file copy). The Load3D image output is a viewport render and can feed image nodes.

### Image-to-3D

Most image-to-3D models are custom packs (for example Hunyuan3D or Stable3D) with their own loader, sampler and mesh output nodes. Read the pack docs and templates, then wire the mesh output to `Preview3DAdvanced` or `SaveGLB`.

### 3D-to-image

Render the mesh in `Load3D`, then pass its image output through a normal image pipeline: upscale, style transfer or background replacement.

### Mesh cleanup

`MergeMeshes` combines multiple mesh inputs. `RotateMesh` fixes orientation using a quaternion or axis mode. `GetMeshInfo` reports vertices and faces, useful for checking that a conversion produced real geometry.

## Validation and pitfalls

- A missing `.glb` in the input folder produces a "Media input missing" or invalid file error. Confirm with `list_assets`.
- The `model_file` value must include the subfolder exactly as stored.
- Large meshes and textures can exhaust RAM or VRAM; reduce texture size or mesh density in the source tool.
- A 3D file is not an image: a Load Image node will reject it, and a Load3D node expects a model file.
- Do not pass the `model_3d` data output into an image input; use the Load3D image output for image nodes.
- Convert other formats to `glb` when a pack accepts only `glb`.
- Check the output node exists; a 3D graph without `SaveGLB` or a preview node is not a final output.
